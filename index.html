Security, Microsoft Graph Permissions & Data Handling

Built on least-privilege, read-only architecture so your security team can approve an audit in minutes.

1. Strictly Read-Only Graph Scopes

ZeroWaste IT never requests write access to your tenant. Live scans only use three read-only application permissions: User.Read.All, AuditLog.Read.All, and Application.Read.All.

2. Zero Credential Storage

Your Tenant ID, Client ID, and Client Secret are transmitted over TLS, held strictly in memory for the duration of the Graph query, and immediately discarded. You can revoke the App Registration at any time.

3. Retention & Compliance Safe

ZeroWaste IT never modifies your Entra ID tenant directly. PowerShell reclamation scripts default to -WhatIf dry-run mode so admins can verify Exchange Litigation Hold or mailbox retention first.

4. Optional Workspace Storage & Support

Audit snapshots are only saved if you sign in and click Save Audit (protected by Row-Level Security in Supabase). Questions or security questionnaires? Email support@profitharborai.com.

ZeroWaste IT — Privacy & Data Retention Policy

Effective November 2026 • Operated by ProfitHarbor AI

1. Entra ID Credentials: Tenant IDs, Client IDs, and Client Secrets submitted for live scans are used strictly in-memory to authenticate against Microsoft Graph and are never written to disk or database tables.

2. Card CSV Uploads: Corporate card CSV files are parsed locally in your browser via JavaScript FileReader; raw CSV files are not uploaded to our servers.

3. Saved Audit Snapshots: Only when you explicitly sign in and click "Save Audit" are summary metrics and findings stored in our encrypted Supabase database under Row-Level Security (RLS) tied to your user ID. You can delete any saved snapshot at any time.

4. Contact: For data deletion or security inquiries, contact support@profitharborai.com.
